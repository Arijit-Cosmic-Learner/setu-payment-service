Developer API Reference

Comprehensive specifications, payload schemas, and live execution tools for the Setu Payment & Settlement Engine.

POST /events

Ingest Payment Lifecycle Event

Ingests an event into the idempotent ledger. Safely transitions transaction state machine and credits accounts.

?? Guaranteed Idempotency: Re-sending the same event_id returns HTTP 200 with "ingestion_status": "already_processed" without duplicate state mutations.
Request Schema
FieldTypeDescription
event_id
Required		UUIDUnique idempotency key for this event.
event_type
Required		Enumpayment_initiated, payment_processed, settled, payment_failed
transaction_id
Required		UUIDUnique ID of the payment transaction.
merchant_id
Required		stringRegistered merchant identifier.
amount
Required		DecimalPositive decimal amount (> 0.00).
Sample Payload
POST /events
{
  "event_id": "b4c064d0-966c-4050-8110-32e5869452b8",
  "event_type": "settled",
  "transaction_id": "edb15f35-809b-4353-9d3c-01fb5a88f537",
  "merchant_id": "merchant_4",
  "amount": "45420.50",
  "currency": "INR",
  "timestamp": "2026-04-08T15:56:25Z"
}

GET /reconciliation/discrepancies

Audit Ledger Discrepancies

Automated auditing engine that flags anomalies like settled_after_failure, processed_not_settled, and stale_initiated.

Discrepancy Types
TypeDescription
settled_after_failure
Funds settled despite gateway failure.
processed_not_settled
Payment captured but not settled.
stale_initiated
Stuck in initiated state with no update.
Live Call
GET /reconciliation/discrepancies
{
  "total_discrepancies": 12,
  "by_type": {
    "processed_not_settled": 12
  }
}
